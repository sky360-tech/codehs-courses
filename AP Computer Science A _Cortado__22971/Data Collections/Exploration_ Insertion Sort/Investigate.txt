1. Predict (arr1: {3, 1, 2})
Before running, visualize the "sorted" wall moving from left to right:
Initial: [3, 1, 2]
Step 1: The 1 is smaller than 3. It shifts 3 over and drops 1 at the start.
Output: [1, 3, 2]
Step 2: The 2 is smaller than 3, but larger than 1. It shifts 3 over and drops 2 in the middle.
Output: [1, 2, 3]
2. Investigate
Why the if (shifted) statement?
It prevents the console from being cluttered with redundant information. If an item is already in its correct relative position (e.g., if you have [1, 2, 3] and you check 3), no "shifting" occurs. Without that if statement, the program would print the exact same array state again, making it harder to see when actual work was done.
Scenario where values won't shift:
Shifting won't happen if the unsortedValue is already greater than or equal to the value to its left.
Example: In the array {1, 2, 5, 4}, when the algorithm reaches 5, it compares it to 2. Since 5 > 2, the while loop never runs, shifted stays false, and no print occurs for that step.
3. Change (arr2: {5, 3, 4, 1, 6, 2})
Expect the following output states:
[5, 3, 4, 1, 6, 2] (Initial)
[3, 5, 4, 1, 6, 2] (3 moves)
[3, 4, 5, 1, 6, 2] (4 moves)
[1, 3, 4, 5, 6, 2] (1 moves to the front)
[1, 2, 3, 4, 5, 6] (2 moves; note that 6 was skipped because it was already in place!)
4. Optional Extension (Reverse Order)
To sort from greatest to smallest, you only need to change the comparison operator in the while loop:
Change: while (sortedIndex > -1 && arr[sortedIndex] > unsortedValue)
To: while (sortedIndex > -1 && arr[sortedIndex] < unsortedValue)
